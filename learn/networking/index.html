CHAPTER 01 · LESSON

The Internet under the hood

Start with the whole path: applications create data, networks carry packets, and protocols coordinate each step.

1.1–1.3 · STRUCTURE

Edge, access, core

Applications run on end systems at the edge. Access networks connect them to routers; the core forwards packets across interconnected networks.

1.3 · SWITCHING

Packets share links

Packet switching divides messages and shares link capacity as packets arrive. Circuit switching reserves a path’s capacity in advance.

1.4 · PERFORMANCE

Delay and throughput

Delay includes processing, queueing, transmission, and propagation. End-to-end throughput is limited by the bottleneck link.

dtrans = L / R
1.5–1.7 · PROTOCOLS

Layers and encapsulation

Each layer provides a service to the one above. Headers are added as data moves down the stack, then removed at the receiver. The chapter closes with network attacks and Internet history.

Key distinction: Transmission delay is the time to place packet bits onto a link; propagation delay is the time those bits travel across it.

CHAPTER 02 · LESSON

Applications at the edge

Applications define the messages exchanged by processes. Transport carries those messages between hosts.

2.1 · ARCHITECTURE

Processes communicate

Client-server applications contact always-on servers. Peer-to-peer applications let hosts act as both clients and servers. Sockets connect an application process to transport.

2.2 · THE WEB

HTTP is request–response

A browser sends an HTTP request; a server returns a response. HTTP is stateless, while cookies and server-side state can support sessions.

2.3–2.4 · MAIL AND DNS

Messages need destinations

SMTP transfers outgoing email between mail servers. DNS is a distributed directory that maps names to records, including host addresses and mail servers.

2.5–2.7 · DISTRIBUTION

Scale the content

Peer-to-peer systems distribute work across hosts. Video services use HTTP streaming and CDNs to place content closer to viewers. Applications use UDP or TCP sockets.

Connection to Chapter 3: HTTP, email, and streaming define application messages; transport protocols determine how those messages move between processes.

CHAPTER 03 · LESSON

Transport: delivery between processes

Transport uses ports to deliver data to the right process. TCP adds reliability, flow control, and congestion control; UDP keeps the service lightweight.

3.1–3.2 · SERVICE

Ports sort the traffic

Multiplexing gathers data from application sockets. Demultiplexing uses port numbers to pass each segment to the correct process.

3.3 · UDP

Connectionless transport

UDP sends independent segments without a handshake or built-in retransmission. Its checksum helps detect errors in a segment.

3.4–3.5 · RELIABILITY

TCP repairs loss

Sequence numbers, acknowledgments, timers, and retransmissions let TCP provide reliable, in-order delivery over IP.

3.5–3.7 · CONTROL

Two different limits

Flow control keeps a fast sender from overwhelming the receiver. Congestion control responds to load inside the network.

Reliable transfer: Go-Back-N retransmits the missing packet and later unacknowledged packets. Selective Repeat retransmits only missing packets and buffers out-of-order arrivals.

    CHAPTER 04 · DATA PLANE

    How routers forward packets

    Routing plans paths across the network. Forwarding moves each arriving packet from a router’s input to its chosen output.

    4.1 · TWO PLANES

    Route, then forward

    The control plane determines routes. The data plane uses a local forwarding table to move each packet to an output link.

    4.2 · ROUTER

    Lookup to output

    An input port examines the packet header; the switching fabric carries it across the router; an output port queues and transmits it.

    4.3 · IP

    Address the destination

    IPv4 and IPv6 datagrams carry addresses. Subnets and longest-prefix matching guide forwarding; NAT translates addresses at network boundaries.

    4.4 · SDN

    Match and act

    Generalized forwarding can match on packet fields and apply actions such as forwarding, dropping, or modifying the packet.

    Queueing matters: If packets arrive at an output faster than its link can send them, they wait in a queue; when the buffer fills, packets are dropped. Scheduling decides which waiting packet goes next.

    CHAPTER 05 · MODULE OUTLINE

    Network Layer: Control Plane

    How routers find paths and coordinate across networks. These modules are mapped here as the next course steps.

    5.1 · MODULE

    Link-state routing

    Routers build a view of network links, then run Dijkstra’s algorithm to find least-cost paths.

    5.2 · MODULE

    Distance-vector routing

    Routers exchange distance estimates with neighbors and update paths using the Bellman–Ford relation.

    5.3 · MODULE

    OSPF and hierarchical routing

    OSPF distributes link-state information inside an autonomous system; areas limit the scope of updates.

    5.4 · MODULE

    BGP and inter-AS routing

    BGP advertises reachability between autonomous systems, combining policy choices with path information.

    5.5 · MODULE

    SDN control plane

    A logically centralized controller can compute and distribute forwarding rules to network devices.

    5.6 · MODULE

    ICMP and network management

    ICMP reports network-layer errors and diagnostics; SNMP provides a framework for monitoring managed devices.

    CHAPTER 06 · MODULE OUTLINE

    Link Layer and LANs

    How neighboring devices deliver frames over a link. These modules are mapped here as the next course steps.

    6.1 · MODULE

    Link services and error detection

    Link protocols frame datagrams and detect corruption with tools such as checksums, parity, and CRC.

    6.2 · MODULE

    Multiple access

    When devices share a medium, access protocols coordinate who transmits and how collisions or contention are handled.

    6.3 · MODULE

    Address resolution

    ARP maps a local IPv4 address to a link-layer address so a frame can reach the next hop.

    6.4 · MODULE

    Ethernet and switching

    Ethernet frames carry datagrams across a LAN; switches learn source addresses and forward frames selectively.

    6.5 · MODULE

    VLANs and data centers

    VLANs divide a switched network into logical broadcast domains; data-center fabrics connect many hosts at scale.

    CHAPTER 07 · MODULE OUTLINE

    Wireless and Mobile Networks

    How networks handle radio links and moving devices. These modules are mapped here as the next course steps.

    7.1 · MODULE

    Wireless link behavior

    Radio signals face attenuation, interference, and multipath; wireless links adapt to changing conditions.

    7.2 · MODULE

    Wi-Fi and local wireless

    802.11 uses association and channel access rules to connect stations through an access point.

    7.3 · MODULE

    Cellular networks

    Cellular architecture connects mobile devices through radio access networks and core-network services.

    7.4 · MODULE

    Mobility and handoff

    Mobility management keeps sessions reachable as a device changes its point of attachment.

    CHAPTER 08 · MODULE OUTLINE

    Security in Computer Networks

    How communication is protected and attacks are detected. These modules are mapped here as the next course steps.

    8.1 · MODULE

    Security foundations

    Threat models identify what an attacker can observe, modify, impersonate, or disrupt.

    8.2 · MODULE

    Cryptography and integrity

    Symmetric and public-key cryptography support confidentiality, message integrity, and digital signatures.

    8.3 · MODULE

    Authentication and signatures

    Authentication verifies identity; signatures bind a message to a signer and help detect changes.

    8.4 · MODULE

    TLS and IPsec

    TLS secures application connections; IPsec protects traffic at the IP layer.

    8.5 · MODULE

    Firewalls

    Firewalls apply traffic rules at network boundaries, while intrusion detection looks for suspicious behavior.

    CHAPTER 09 · MODULE OUTLINE

    Multimedia Networking

    How networks deliver audio and video under timing constraints. These modules are mapped here as the next course steps.

    9.1 · MODULE

    Multimedia applications

    Audio and video traffic has timing and rate needs that differ from ordinary file transfers.

    9.2 · MODULE

    Streaming video

    Adaptive streaming selects chunk quality based on bandwidth, buffer state, and playback conditions.

    9.3 · MODULE

    VoIP and real-time audio

    Real-time voice systems trade a small amount of loss tolerance for low end-to-end delay.

    9.4 · MODULE

    RTP and SIP

    RTP carries real-time media; SIP helps establish, manage, and end multimedia sessions.

    9.5 · MODULE

    Quality of service

    QoS tools such as scheduling, resource reservation, and Diffserv classes can manage competing traffic.
