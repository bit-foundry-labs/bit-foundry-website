CHAPTER 05 · GUIDED LESSONS

Network Layer: Control Plane

How routers find paths and coordinate across networks. Open any module for a five-page lesson with an explanation, a worked example, guided practice, and a checkpoint.

5.1 · MODULE

Link-state routing

Routers build a view of network links, then run Dijkstra’s algorithm to find least-cost paths.

Link-state routers learn the network graph and link costs, then run Dijkstra’s algorithm to find least-cost paths. Link-state advertisements keep topology views aligned; each router computes its own forwarding choices.

In practice: When a link cost changes, routers advertise the update and recompute paths.

5.2 · MODULE

Distance-vector routing

Routers exchange distance estimates with neighbors and update paths using the Bellman–Ford relation.

Distance-vector routers exchange destination costs with neighbors and apply Bellman–Ford: route cost equals link cost to a neighbor plus that neighbor’s advertised cost. Updates can converge slowly after failures.

In practice: A neighbor may offer a cheaper route, but bad news can spread slowly and create count-to-infinity behavior.

5.3 · MODULE

OSPF and hierarchical routing

OSPF distributes link-state information inside an autonomous system; areas limit the scope of updates.

OSPF is an intra-autonomous-system link-state protocol. Routers flood advertisements, build a shared topology database, and compute paths; areas and designated routers help limit overhead.

In practice: A campus can keep detailed routes inside areas and use summaries between them.

5.4 · MODULE

BGP and inter-AS routing

BGP advertises reachability between autonomous systems, combining policy choices with path information.

BGP exchanges reachability between autonomous systems using path-vector advertisements. Operators choose routes using attributes and policy, not just hop count; AS-PATH helps prevent loops and NEXT-HOP identifies the next router.

In practice: Providers may choose different paths because of business relationships or traffic-engineering goals.

5.5 · MODULE

SDN control plane

A logically centralized controller can compute and distribute forwarding rules to network devices.

An SDN controller maintains a network view and programs forwarding devices through a protocol such as OpenFlow. Control applications can implement routing, access policy, or traffic engineering; devices still forward packets.

In practice: A controller can coordinate changes across several switches after one policy update.

5.6 · MODULE

ICMP and network management

ICMP reports network-layer errors and diagnostics; SNMP provides a framework for monitoring managed devices.

ICMP carries network-layer errors and diagnostics, supporting ping and traceroute. SNMP uses a manager-agent model to read device counters and configuration; management data helps operators assess network health.

In practice: Interface error counters can reveal a bad link; ICMP time-exceeded messages help trace a route.
