CHAPTER 02 · LESSON

Applications at the edge

Applications define the messages exchanged by processes. Transport carries those messages between hosts.

2.1 · ARCHITECTURE

Processes communicate

Client-server applications contact always-on servers. Peer-to-peer applications let hosts act as both clients and servers. Sockets connect an application process to transport.

Application architecture describes which processes communicate and where they run. Client-server systems use an often-available server; peer-to-peer systems let hosts request and provide service. A socket connects an app to transport.

In practice: A mobile app opens a socket to an API; a file-sharing app can connect to several peers.

2.2 · THE WEB

HTTP is request–response

A browser sends an HTTP request; a server returns a response. HTTP is stateless, while cookies and server-side state can support sessions.

HTTP is request-response: a client asks for a resource and a server returns a status, headers, and possibly a body. Persistent connections reuse TCP; caches avoid round trips; cookies carry state.

In practice: A browser can reuse one connection for several assets and load a repeat image from cache.

2.3–2.4 · MAIL AND DNS

Email is a journey across systems

DNS MX records locate receiving mail servers; SMTP relays and queues messages; IMAP or POP3 gives recipients mailbox access.

Email uses DNS for destination discovery and SMTP for submission and server-to-server relay. Receiving servers can accept messages into durable queues; mailbox access happens afterward through a separate service.

In practice: Inspect MX records, SMTP response codes, queue age, and mailbox filtering as separate checkpoints.

2.5–2.7 · DISTRIBUTION

Scale the content

Peer-to-peer systems distribute work across hosts. Video services use HTTP streaming and CDNs to place content closer to viewers. Applications use UDP or TCP sockets.

DNS is a distributed directory mapping names to records. Peer-to-peer apps distribute work among hosts; video services use adaptive HTTP streaming and CDNs to put content near viewers.

In practice: DNS resolves a site’s name, then a CDN can direct the browser to a nearby cache.

Connection to Chapter 3: HTTP, email, and streaming define application messages; transport protocols determine how those messages move between processes.
