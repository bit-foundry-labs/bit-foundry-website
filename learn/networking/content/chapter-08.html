CHAPTER 08 · GUIDED LESSONS

Security in Computer Networks

How communication is protected and attacks are detected. Open any module for a five-page lesson with an explanation, a worked example, guided practice, and a checkpoint.

8.1 · MODULE

Security foundations

Threat models identify what an attacker can observe, modify, impersonate, or disrupt.

Security starts with a threat model: identify assets, attackers, and needed guarantees. Common goals include confidentiality, integrity, authentication, and availability; each mechanism addresses particular threats.

In practice: A login API may need to hide passwords in transit, verify the server, and limit repeated guesses.

8.2 · MODULE

Cryptography and integrity

Symmetric and public-key cryptography support confidentiality, message integrity, and digital signatures.

Symmetric cryptography uses a shared secret for efficient encryption; public-key cryptography uses a key pair to establish secrets or prove identity. Protocols combine them because public-key operations cost more for bulk data.

In practice: TLS can use public-key techniques during setup, then protect session data with symmetric encryption.

8.3 · MODULE

Authentication and signatures

Authentication verifies identity; signatures bind a message to a signer and help detect changes.

A cryptographic hash produces a digest; a message authentication code uses a secret to detect tampering and authenticate a sender. Digital signatures use a private key to sign and a public key to verify.

In practice: A signed software release lets users check who created it and whether the file changed.

8.4 · MODULE

Endpoint authentication

Fresh challenges and certificate validation help a client prove which server it is talking to and resist replay.

Endpoint authentication must distinguish a real participant from an impostor, even when messages can be replayed. Nonces and challenge-response exchanges make old authentication messages unusable in a new session.

In practice: A fresh random challenge prevents a captured response from simply being replayed later.

8.5 · MODULE

Applied network security

Secure email, TLS, IPsec/VPNs, wireless protection, firewalls, and intrusion detection protect different trust boundaries.

Secure email combines encryption for confidentiality with signatures or message authentication for integrity and sender verification. PGP packages these tools around user-managed keys; key distribution and trust remain part of the problem.

In practice: Encryption hides message contents from intermediaries; a signature helps verify who sent it.
