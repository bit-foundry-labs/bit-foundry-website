ForgeLoop is for developers managing more than one active project who are tired of restating context and repeatedly asking an agent to continue. It moves only through a preapproved sequence and stops when judgment is needed.

01

Approve

Set the goal, boundaries, and ordered steps you are willing to delegate.

02

Work

Run checks and bounded work in an isolated worktree with explicit limits.

03

Report

Keep evidence, failed attempts, and the resulting state visible for inspection.

04

Decide

You review changes and decide what, if anything, ships.

More momentum, less oversight theater.

Autonomy needs edges.

ForgeLoop’s promise is not “hands off forever.” It is less babysitting without surrendering control over cost, code, or release decisions.

Local-first

Your work stays close to your machine and your chosen model access. It is designed around user control, not mandatory hosted infrastructure.

Bounded execution

Objectives carry step counts, retry budgets, and stop states. Reaching a limit produces an explanation, not a hidden continuation.

Human release control

ForgeLoop does not automatically push, open pull requests, merge, deploy, or send messages on your behalf.

Built with working developers, not a feature checklist.

We are opening a small set of conversations with people who manage several software projects and want a local-first system for keeping approved work moving.
